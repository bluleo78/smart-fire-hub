# SqlValidator 함수 허용목록 — PostGIS/postgis_topology 확장 소유 함수 중 "부작용 없음(non-volatile)"만.
# (#385 최종 리뷰 — deny-list → 허용목록 전환)
#
# 생성 쿼리(수정 시 이 쿼리를 재실행해 갱신할 것):
#   SELECT p.proname FROM pg_proc p
#     JOIN pg_depend d ON d.objid = p.oid AND d.deptype = 'e'
#     JOIN pg_extension e ON e.oid = d.refobjid
#    WHERE e.extname IN ('postgis','postgis_topology')
#    GROUP BY p.proname
#    HAVING bool_and(p.provolatile <> 'v')
#    ORDER BY 1;
#
# 왜 provolatile 로 거른 함수 "이름"만 남기는가(오버로드가 아니라 이름 단위):
# SqlValidator 는 함수 호출을 이름으로만 매칭하고 인자 타입/개수는 보지 않는다(JSqlParser 는 오버로드
# 해석을 하지 않는다). 그래서 이름 단위로 "모든 오버로드가 non-volatile"인 것만 남겨야 한다 — 오버로드
# 하나라도 volatile(부작용 있음)이면 그 이름 전체를 제외했다(HAVING bool_and(...)). 실측: 이 필터로
# dropgeometrycolumn/addgeometrycolumn/createtopology/droptopology/updategeometrysrid/addtosearchpath
# 등 스키마를 변경하는 위험 함수(all volatile)가 전부 제외됐고, ST_AsGeoJSON/ST_X/ST_Area 등 순수
# 계산 함수(immutable/stable)만 남았다(전체 643개 중 아래 개수, 2026-08-17 test DB PostGIS 버전 기준).
# postgis_topology 의 관리용 함수도 volatile 이라 자동으로 빠진다.
#
# 왜 pg_catalog(표준 SQL 내장 함수)는 이렇게 유도하지 않는가: current_setting/pg_get_viewdef/
# table_to_xml/database_to_xml 이 모두 provolatile='s'(stable)로 표시돼 있어 이 필터로는 걸러지지
# 않는다(실측) — pg_catalog 표준 함수는 SqlValidator.SQL_STANDARD_FUNCTIONS 에 손으로 큐레이션한다.
#
# 이 파일은 손으로 입력한 목록이 아니라 위 쿼리의 출력을 그대로 붙여넣은 것이다 — 갱신 시에도 쿼리
# 결과를 그대로 덮어쓸 것(부분 수정 금지, 손 편집은 실수로 항목이 빠지거나 잘못 추가될 위험이 있다).
#
# 형식: 한 줄에 함수 이름 하나(소문자), '#'로 시작하는 줄은 주석으로 무시한다.
