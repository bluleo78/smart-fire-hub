# WD-767 스마트 작업 리포트 수치 출처 검증 — 설계

## 왜
스마트 작업 리포트에 SQL 결과에 없는 수치(모델이 직접 더한 합계, 지어낸 목표치·비율)가 섞였다(job 1 #6~#10). 집계는 SQL 이 맞게 하고, 틀어지는 곳은 LLM 이
문장·HTML 을 쓰는 단계다. 사람이 리포트를 받기 전에 「출처가 확인되지 않은 수치」를 알아챌 수 있어야 한다.

## 받은 결정(2026-11-16 양동희 「추천대로」)
- 범위: ① 수치 검증 ② report-writer 지침 강화 ③ 원본 결과(JSON) 전달. ④ 양식 편집 화면 안내는 별도 이슈.
- 불일치 시: **경고만** — 실행 결과에 「출처 확인 안 된 수치 n개」 목록을 남기고 리포트 화면·알림에 표식, 발송은 그대로. 추가 LLM 호출 없음.
- 허용 파생값: 도구 결과에 있는 값과 그 표기 변환(억·만·천·조 단위 환산, 쉼표, 반올림해 표시 자릿수가 같은 값), 날짜·연도·서수(1위, 3개 섹션), 양식·프롬프트에 원래 있던 숫자.
  모델이 계산한 합계·증감률·비중, 목표·전망 수치는 불허 — SQL 결과에 있어야 통과.

## 목표
1. **ai-agent 수치 검증**(`routes/proactive.ts`): 실행 중 데이터 조회 도구(`execute_analytics_query`·`execute_sql_query`·`query_dataset_data`, 공급자 접두사 무관)의
   `tool_result` 문자열을 모으고, 리포트 본문(report.md + summary.md, md 가 없으면 report.html 의 텍스트)의 숫자를 그 결과의 숫자와 대조한다.
   응답에 `numberCheck: { checked, unverified: [{ text, context }], unverifiedTotal }` 를 싣는다.
   - 데이터 조회 결과가 하나도 없으면 대조할 근거가 없으므로 `checked=false`(경고 없음).
   - `unverified` 는 앞 20개, `unverifiedTotal` 은 전체 수. 같은 표기는 한 번만.
2. **report-writer 지침**(`subagents/report-writer/agent.md`): 「계산하지 않는다 — 합계·증감률·비중은 입력 데이터에 있는 값만」, 「목표·전망·권고 수치를 만들지 않는다」,
   「데이터에 없는 값을 요구하는 섹션은 『데이터 없음』으로 쓴다」를 기본 규칙으로 넣고, 「절대값과 변화율 병기」 원칙은 「데이터에 변화율이 있을 때만」으로 고친다.
   VERIFY 단계에 「본문의 모든 숫자가 입력 데이터에 있는지」 점검을 더한다.
3. **원본 결과 전달**(`delegationPromptParts`·프로액티브 시스템 프롬프트): 메인 에이전트가 report-writer 위임 프롬프트에 조회 결과를 **원문 JSON 그대로**
   「원본 데이터」 블록으로 넣게 지시한다(요약·재서술 금지, 계산이 필요하면 SQL 로 다시 조회).
4. **api**: `ProactiveResult` 에 `numberCheck` 를 더해 `proactive_job_execution.result` JSONB 에 그대로 저장(마이그레이션·저장소 변경 없음).
   알림 세 경로(outbox `ProactiveJobNotificationMapper`, 직접 `ChatDeliveryChannel`·`EmailDeliveryChannel`)의 요약 앞에
   `⚠ 출처를 확인하지 못한 수치 {n}개가 있습니다 — 실행 결과 화면에서 확인하세요.` 한 줄을 두고 빈 줄 뒤에 요약을 잇는다(`unverifiedTotal > 0` 이고
   `checked` 일 때만, 요약이 비면 경고 줄만). 앞에 두는 이유: 카카오·슬랙 등 채널이 긴 본문을 잘라도 경고가 남게 하려는 것.
5. **web**: 실행 상세(`ExecutionDetailPage`)에 `unverifiedTotal > 0` 이면 경고 배너 「출처를 확인하지 못한 수치 {n}개」와 수치·앞뒤 문맥 목록을 보인다.

## 수치 대조 규칙
- 리포트 숫자 토큰: `[-+]?\d{1,3}(,\d{3})+(\.\d+)?|[-+]?\d+(\.\d+)?` 뒤에 선택적 단위(`조|억|만|천`)·`원`·`%`.
- 건너뛰는 토큰(허용): 날짜·시각(`YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`, `HH:MM`), 연도(`19xx|20xx` 뒤 `년` 또는 단독 4자리 연도),
  `월`·`일`·`시`·`분`·`초`·`주`·`분기` 가 붙은 수, `Q1~Q4`, 서수(`위|번째|차|등|순위|주차` 가 붙은 수), 단위·% 없는 정수 0~10,
  양식·프롬프트·context 텍스트에 같은 표기로 있는 수.
- 출처 값: 모은 도구 결과 텍스트의 모든 숫자 리터럴(쉼표 없는 JSON 숫자, 지수 표기 포함).
- 일치: 표시값 d(표시 단위 u 의 배수 m, 소수 자릿수 k)에 대해 출처 값 s 중 `round(|s|/m, k) == |d|` 인 것이 있으면 통과.
  `%` 는 `round(|s|, k)` 또는 `round(|s|*100, k)` 가 같으면 통과. 부호는 보지 않는다(「-3」과 「3 감소」).

## 하지 않는 것
- 재작성 요청·발송 보류(결정 (나)·(다) 아님). 실행 목록 화면 표식(요약 DTO·두 벌 저장소 변경이 필요 — 상세 화면과 알림으로 충분).
- 양식 편집 화면 안내(④ → 별도 이슈). opencode 경로의 위임 프롬프트(위임이 없다 — `OPENCODE_REPORT_GUIDE` 에 같은 규칙 한 줄만 더한다).

## 접근
- (가) ai-agent 에서 검증해 응답에 싣고 api 는 저장·전달만 — **채택**. 도구 결과 원문은 ai-agent 에만 있다.
- (나) api 가 MCP 호출 로그로 검증 — 도구 결과 원문을 api 가 따로 남기지 않아 저장 부담이 크다.
- (다) LLM 검증 — 비용·비결정성. 결정 (가) 「추가 비용 없음」과 어긋난다.

## 내가 정한 것
- 대조 대상은 md·summary(HTML 은 스타일 숫자가 섞여 md 가 없을 때만 텍스트로).
- 데이터 조회 결과가 없으면 검증하지 않는다(모든 숫자가 경고가 되는 소음 방지).
- 도구 결과가 크기 상한으로 잘렸으면 잘린 뒤 행의 수치는 경고가 될 수 있다 — 경고만이라 받아들인다.
- `tool_use` 이벤트에 `toolUseId` 를 더해 `tool_result` 와 짝짓는다. 짝을 못 찾으면 직전 `tool_use` 이름으로 판단한다.
- 단위·% 없는 정수 0~10 은 개수·서수로 보고 건너뛴다.
