# WD-781 스마트 작업 수치 검증 — 단위 값 출처·계산한 증감률 오탐 고치기

## 원인(재현: report-number-check 단위 시험)
1. 조회 결과가 이미 표시 단위로 된 값(`{"올해억":1.3}`)이면, 리포트의 「1.3억」 토큰은 value=1.3·multiplier=1e8 이라 `matchesSource` 가 출처 1.3 을 1e8 로 나눈 값(1.3e-8)과 비교해 못 찾는다. → 0.3억·1.3억·7.7억·11.7억 오탐.
2. 「111.8 → 28.8시간 (-74.2%)」처럼 출처 두 값으로 맞게 계산한 증감률은 출처에 그 값이 없어서 늘 경고된다. 확인할 점의 「마지막 조회 결과 누락」은 아니다 — Q7 의 다른 값(구독·기술 서비스 행)은 모였고, 억 단위 수치만 걸렸다.

## 바꿀 것 — `apps/firehub-ai-agent/src/agent/report-number-check.ts`
1. **단위 값 출처**: 단위(천·만·억·조·복합)가 붙은 토큰은 지금 규칙(출처 ÷ 배수) 외에, 출처 값 자체가 표시값과 같으면(표시 자릿수 반올림 비교) 맞는 것으로 본다. 출처 열이 이미 그 단위로 집계된 경우다.
2. **계산한 증감률·비율**: % 토큰이 출처·허용 텍스트로 확인되지 않으면, **같은 줄**(줄바꿈 기준 — 표 한 행, 목록 한 항목)에 있는 **확인된**(출처·허용 텍스트와 맞은) % 아닌 토큰 둘 a, b(실제 값 = value×multiplier, a≠0)의 순서쌍마다
   - 증감률 (b−a)/a×100, 비율 b/a×100 을 표시 자릿수로 반올림해 표시값(부호 없는 절댓값)과 같으면 맞는 것으로 본다.
   - 확인되지 않은 수치끼리는 짝을 짓지 않는다 — 지어낸 두 값으로 지어낸 비율을 통과시키지 않게.
   - 같은 줄 안만 보므로 쌍 수가 작다(출처 전체 쌍을 돌지 않는다).

## 내가 정한 것
- 단위 값 출처 허용으로 「1.3억」이 무관한 출처 1.3 에 우연히 맞을 수 있다. 경고 전용 기능이고 거짓 경고가 더 큰 해라 받아들인다.
- 증감률 범위는 같은 줄. 문장 단위 분리는 「111.8 → 28.8」 같은 표기에 맞지 않을 수 있어 줄로 한다. %p 차이는 이번 범위 밖.
- WD-775(developer5, 같은 파일의 matchesSource 재작성)와 겹친다 — 먼저 머지되는 쪽에 맞춰 rebase 때 내가 합친다.

## 시험
- 이슈 표의 5건(0.3억·1.3억·7.7억·11.7억·-74.2%)이 경고되지 않는다.
- 같은 줄에 확인되지 않은 수치로 만든 비율, 다른 줄 값으로 만든 비율, 틀린 증감률은 여전히 경고된다.
- 기존 시험 그대로 통과.

## 구현하며 좁힌 것
- 단위 값 출처 비교는 표시값에 소수가 있을 때만 한다 — 기존 시험(「5천만」「5억」은 출처 5 로 확인되지 않음)과 WD-775 의 「15조 편성」 경고 시험에 맞춤. 억 단위 열의 정수(「15억」)는 여전히 경고된다.
- 증감률 재료는 날짜·시각·분기만 가린 토큰(접미사·작은 정수 포함) 중 확인된 것 — 「28.8시간」은 대조 대상에서 빠지지만 증감률의 재료가 된다.
- 남은 위험: 한 줄에 확인된 수치가 많으면(넓은 표 행) 순서쌍이 늘어 지어낸 %가 우연히 맞을 확률이 커진다(경고 전용이라 감수).
