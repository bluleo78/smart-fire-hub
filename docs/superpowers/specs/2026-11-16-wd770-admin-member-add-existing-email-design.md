# WD-770 운영자 콘솔 멤버 추가 — 「새 계정」 탭의 기존 이메일 안내 (작은 변경)

## 왜
테넌트 상세 › 멤버 추가 › 「새 계정」 탭에 이미 계정이 있는 이메일을 넣으면 서버(`TenantMemberAdder`)는 username(=정규화 이메일)으로
기존 계정을 찾아 멤버십만 붙이고 `created=false` 를 준다. 입력한 이름·임시 비밀번호는 쓰지 않는다. 지금 화면은 이때 「<입력한 이름>님을
멤버로 추가했습니다」 토스트만 띄우고 닫아, 운영자가 복사해 둔 임시 비밀번호가 적용되지 않았다는 것을 모른다(WD-750 리뷰 비차단 결함).

## 목표
1. **제출 전 안내**(WD-751 웹 방식과 맞춤): 「새 계정」 탭 이메일 칸에서 포커스가 빠지면(형식이 맞을 때) 플랫폼 사용자 검색
   (`GET /api/platform/users?q=`)으로 그 이메일의 계정이 있는지 본다. 검색 결과 중 `email` 이 정규화(trim·소문자) 이메일과 같은 계정이
   있으면 칸 아래에 「이미 가입된 계정입니다 — <이름>(<이메일>). 새 계정을 만들지 않고 이 계정을 멤버로 추가합니다.」 안내와
   「기존 계정으로 추가」 버튼을 보인다. 버튼은 「기존 계정」 탭으로 바꾸고 그 계정을 골라 둔다(ADMIN 체크는 그대로).
2. **제출 뒤 안전망**: 「새 계정」 탭 요청에 `created=false` 가 오면(사전 확인이 놓친 경우 — username≠email 계정, 검색 실패, 확인 전 제출)
   경고 토스트 「이미 있는 계정(<정규화 이메일>)이라 기존 계정으로 추가했습니다 — 입력한 이름·임시 비밀번호는 쓰지 않았습니다」를 보이고
   닫는다. 이름은 서버가 주지 않으므로 입력한 이름 대신 실제 로그인 아이디(이메일)를 보인다.
3. **같은 리뷰의 선택 항목**: 로그인한 운영자가 `/signup` 을 직접 열면 첫 가입 폼 대신 `/tenants` 로 보낸다. (「가입은 됐는데 로그인
   실패」 구분은 WD-749 에서 이미 `SignupSessionError`·「계정은 만들어졌습니다. 로그인해 주세요.」로 들어가 있어 할 것이 없다.)

## 하지 않는 것
- API 변경 없음(응답에 계정 이름 추가, 존재 확인 전용 API 등). 검색 API 는 `platform:member:read` 권한으로 이미 화면이 쓰는 것이다.
- 안내가 떠도 「새 계정」 탭 제출을 막지 않는다 — 막지 않아도 안전망이 결과를 분명히 알린다.
- 이미 멤버인지 사전 판정하지 않는다(서버 409 `MEMBER_ALREADY_EXISTS` 안내가 그대로 있다).

## 접근
- (가) 제출 전 확인 + 안전망 — **채택**. 이슈가 권한 웹(WD-751) 방식과 맞추고, 확인이 놓치는 경우도 안전망이 덮는다.
- (나) 안전망만 — 가장 작지만 운영자가 비밀번호를 복사·전달하기 전에 알 수 없다.
- (다) 서버 응답에 계정 이름 추가 — API·두 벌 저장소 변경이 필요한데 얻는 것은 토스트의 이름뿐이다.

## 내가 정한 것
- 사전 확인 일치 기준은 검색 결과의 `email` 정확 일치(대소문자 무시). 검색 API 는 username 을 돌려주지 않아 username≠email 계정은 놓치며, 안전망이 덮는다.
- 검색 실패·진행 중에는 안내를 띄우지 않는다(조용히 넘어가고 안전망에 맡긴다).
- 이메일을 다시 고치면 안내는 새 확인 결과로 바뀐다(이전 결과를 남기지 않는다).
