# WD-777 API 연결 상세 편집 — 재조회 병합 설계

## 왜
WD-763 은 인증 편집 중 재조회가 오면 「하나라도 고쳤으면 인증 칸 전체를 지키고, 아무것도 안 고쳤으면 전체를 새 값으로」 했다. 리뷰에서 다음 결함이 남았다(이슈 본문 1~5).
1. 기본 정보(이름·설명·baseUrl·healthCheckPath)는 재조회 때마다 전부 서버 값으로 덮인다(저장 안 한 설명이 인증 저장 뒤 사라짐).
2. 스냅샷이 열 때 값에 고정돼, 저장 직후 재조회 전에 연 편집이 옛 가린 키(`****K1`)를 보내 400.
3. 추가 헤더 행을 배열 참조로 비교해, 빈 행을 더했다 지우면 계속 「건드림」이라 남의 변경을 못 받고 덮어쓴다.
4. `keepAuthEdits` 가 refill 효과 의존성이라, 고친 칸을 스냅샷 값으로 되돌리는 순간 전체가 서버 값으로 바뀐다.
5. 다시 채우면 인라인 오류가 모두 지워진다(칸은 여전히 틀림).

## 고칠 것 — 칸별 3-way 병합
기준(스냅샷)은 **늘 마지막으로 받은 서버 응답**이다. 새 응답이 오면(같은 응답 참조면 아무것도 안 함) 칸마다:
- 지금 칸 값 == 이전 기준 값(고치지 않음) → 새 서버 값으로 바꾼다.
- 다르면(고침) → 지금 값을 둔다.
- 기준은 새 응답으로 바꾼다 → 고친 칸은 여전히 「고침」(미저장 경고 유지), 가린 키·비밀번호(빈 칸 = 유지)도 새 응답 값이다(결함 2).

적용 범위:
- **기본 정보**(결함 1): 이름·설명·baseUrl·healthCheckPath 를 칸별로. 기준은 `initialInfo`.
- **인증 편집 중**: 인증 방식·키 위치·헤더 이름·파라미터 이름·Basic 아이디를 칸별로. 추가 헤더 행은 **한 덩어리**로 — 지금 행 내용이 이전 기준 행 내용과 같으면 새 행으로 바꾼다. 비밀 칸(키·토큰·비밀번호)은 채우지 않는다(입력값 그대로).
  - 추가 헤더 덩어리를 고쳐 지킬 때도, 그 안의 손대지 않은 저장 행(이전 기준 행과 이름·값이 같은 행)의 가린 값은 새 기준의 같은 이름 행 값으로 맞춘다(새 기준에 그 이름이 없으면 그대로) — 추가 헤더 비밀 값도 「기준은 늘 최신」(리뷰 후속).
- 편집이 닫혀 있으면 지금처럼 인증 칸을 채우지 않고, 열 때 그때의 연결로 채운다.

부수:
- **추가 헤더 비교는 내용으로**(결함 3): 행 수와 행별 이름·값(빈 행 포함, id 무시)이 같으면 같다. 「건드림」과 「고침」을 이 비교 하나로 본다(빈 행 추가도 고침으로 잡혀 미저장 경고 — WD-763 과 같음).
- **병합은 새 응답이 올 때만**(결함 4): 효과 의존성은 연결 응답과 편집 여부뿐 — 타이핑으로 다시 채우지 않는다.
- **오류는 바뀐 칸만 지운다**(결함 5): 새 값으로 바꾼 칸의 인라인 오류만 비우고, 지킨 칸·비밀 칸 오류는 둔다. 추가 헤더 오류는 행을 바꿨을 때만 비운다. 기본 정보도 같다.
- 정리(6~8): 추가 헤더 「고침」은 키 수 + `isSameFormValue` 대신 평범한 값 비교. 스냅샷을 state 하나(기준 + 그 응답)로 모아 `authSeededFromRef` 를 없앤다. 스냅샷의 추가 헤더 행은 인자 응답에서 만든다.

## 하지 않는 것
- 서버 쪽 변경, 낙관적 잠금(updatedAt 충돌 창) 도입 — 이 화면엔 아직 없다.
- 비밀 칸 병합 — 입력한 비밀은 서버 값과 비교할 수 없다.

## 내가 정한 것
- 「하나라도 고치면 전체 보존」(WD-763) 대신 칸별 병합. 이슈의 결함 1·3·4 가 모두 「고치지 않은 칸까지 지키거나 덮는」 데서 왔고, 칸별로 보면 한 규칙으로 풀린다. 고친 인증 방식과 서버가 바꾼 키 위치가 섞일 수 있으나, 저장은 지금 칸 전체를 보내므로 화면에 보이는 그대로 저장된다.
- 추가 헤더는 행 단위가 아니라 덩어리로 병합한다 — 행에는 서버 쪽 안정 id 가 없어 행끼리 짝지을 수 없다.

## 시험(E2E, 재조회는 route 가로채기로 늦추거나 두 번째 응답을 바꿔 재현)
1. 설명을 고친 채 인증 저장 → 재조회 뒤에도 설명 유지·미저장 경고. 고치지 않은 이름은 새 값.
2. K2 저장 뒤 재조회가 늦을 때 편집을 열고 헤더 이름만 바꾼 뒤 재조회가 오고 나서 저장 → 요청 `apiKey` 가 새 가린 값(`****K2`).
3. 헤더 추가 → 빈 행 삭제 → 다른 값으로 재조회 → 추가 헤더가 새 값으로 바뀐다.
4. 헤더 이름을 고치는 중 재조회(헤더 이름·다른 칸 변경) → 헤더 이름은 내 값, 다른 칸은 새 값. 이어 헤더 이름을 원래 값으로 되돌려도 다른 칸이 바뀌지 않는다(되돌린 순간 다시 채우지 않음).
5. 헤더 이름을 비워 오류를 띄운 채 재조회 → 오류 유지.
