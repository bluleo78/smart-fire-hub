# WD-821 — 통합 PR #1059 반려 반영 설계 (짧은 설계)

무인 work-loop 세션이라 설계 승인은 스스로 했다. 반려 사유 넷: 절차 생략, E2E 없음, 남은 대화상자의 운영 빌드 수치 없음, 대시보드 키보드 결함 미등록.

## 의도
저사양(CPU 4x)에서 대화상자 열기 클릭이 장기 작업(50ms 넘음)으로 이어지지 않게 한다. INP 200ms 아래를 유지한다.
코드는 원인이 확인된 곳만 고친다(차트 빌더 「저장」의 recharts 재계산). 나머지는 운영 빌드 수치로 근거를 남긴다.

## 운영 빌드 4x 측정(정찰 — 최종 HEAD d00276a2a, `E2E_SERVER=preview`, API 모킹, 5회+1x 대조)
| 대상 | 4x 클릭→페인트 | 장기 작업 |
|---|---|---|
| 사용자 관리 「멤버 추가」 | 40ms | 0 |
| 쿼리 에디터 「저장」 | 40~48ms | 0 |
| 「새 대시보드」 | 40ms | 0 |
| 관리자 API 연결 「새 연결」 | 48ms | 0 |
| 차트 빌더 「저장」(빌더 한정 memo) | 48ms | 0 |
| 카테고리 새로·수정(대조) | 40~48ms | 0 |

200ms 를 넘는 곳이 없다. 남은 비용(약 25ms)은 Radix Presence `getAnimationName`(열림 애니메이션 확인용 getComputedStyle)과 FocusScope 포커스 이동이다. 모든 대화상자에 공통이고 라이브러리 고유 비용이라 이번에는 고치지 않는다.
원자료: `.work-loop/state/evidence/WD-821/wd821-remaining-prod.json`(로컬), 측정 spec 은 임시라 저장소에 남기지 않았다.

## 접근
- **A(선택)**: 차트 빌더 미리보기만 `MemoChartRenderer`(React.memo)로 감싼다. 원인 지점만 바꾸고, 대시보드 그리드는 손대지 않는다.
- B: `ChartRenderer` 를 전역 memo 로 감싸고 대시보드 키보드 배치 경합도 함께 고친다. 대시보드 그리드(react-grid-layout) 동작을 바꿔야 해 범위가 커진다. 그래서 WD-823 으로 나눴다.
- C: `ChartBuilderPage` 안에서 `useMemo` 로 차트 요소를 고정한다. A 와 효과가 같지만 단위 테스트로 고정하기가 어렵고, 재사용할 수 없다.

## 목표 / 비목표
- 목표: E2E 로 (1) 저장 대화상자를 열고 닫아도 미리보기 차트가 그대로 있고, (2) 차트 종류·축을 바꾸면 미리보기가 갱신되는 것을 고정한다. `MemoChartRenderer` 주석에 WD-823 을 남긴다.
- 비목표: Radix 대화상자 공통 비용 줄이기, 대시보드 키보드 경합(WD-823).
- 반목표: 미리보기가 설정을 바꿔도 갱신되지 않는 것. memo 가 낡은 화면을 남기면 실패다.

## 빌더에게 남긴 것
- E2E 는 기존 `e2e/pages/analytics/` 의 차트 빌더 spec·모킹 헬퍼를 재사용한다. 위치·파일 이름은 구현자가 정한다.
- 「그대로」는 대화상자 전후에 미리보기 SVG 가 남아 있고 같은 축 정보를 보인다는 뜻이다. 다시 그렸는지까지는 E2E 로 보지 않는다(렌더 횟수는 단위 테스트가 본다).
